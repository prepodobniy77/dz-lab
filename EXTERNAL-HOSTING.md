# DZ LAB: GitHub и внешний Cloudflare

## Текущее состояние

В main импортированы исходники архива dz-lab-v15.zip. Это исходная версия Sites, а не подтверждённая внешняя публикация. Исходный импорт: 4717c4c9260bccb666653321eba43e44f850ae01.

Приложение: React 19, Vinext, Vite, Cloudflare Workers и D1. Каталог в data/catalog.json входит в репозиторий; рабочие данные D1 и секреты Sites в архив не входят.

## Совместная работа

Codex и Claude Code должны работать с этим репозиторием. Для каждой задачи используйте отдельную ветку и pull request. Перед началом обновляйте ветку от main. Не заменяйте проект повторным импортом архива.

Версии инструментов указаны в package.json: Node.js >=24 и pnpm 11.25.0. Начните с pnpm install --frozen-lockfile, затем pnpm exec tsc --noEmit и node --test tests/*.test.mts. Часть тестов требует установленный Wrangler/Miniflare. scripts/install-pnpm.sh ориентирован на управляемую Linux-среду Sites, поэтому для обычного клона используйте непосредственно pnpm.

## Что адаптировать перед внешней публикацией

1. Создать отдельную конфигурацию Wrangler с именем Worker и реальным идентификатором новой D1 в аккаунте владельца. Сейчас vite.config.ts содержит заглушку database_id.
2. Отделить внешнюю сборку от Sites и preview-интеграций. Сохранить согласованную связку Vinext и Cloudflare Vite plugin из lockfile; не обновлять зависимости без необходимости.
3. Настроить внешний вход. app/chatgpt-auth.ts доверяет заголовкам oai-authenticated-user-*, которые на Sites добавляет доверенный прокси. На внешнем публичном Worker нельзя принимать такие заголовки от клиента: нужна проверенная сессия или другой проверенный механизм идентификации. TRUST_OAI_HEADERS должен оставаться 0. Проверить сохранение сборок, ручное обновление и MCP.
4. Применить миграции drizzle к новой D1. Если нужны текущие сохранённые сборки, история и новые цены, экспортировать данные существующей базы отдельно; data/catalog.json не является экспортом D1.
5. Настроить серверные секреты в Cloudflare; значения не коммитить. .env.example содержит перечень переменных.
6. Подключить GitHub к Workers Builds после проверки внешней сборки. Для расписания выбрать одного основного исполнителя, чтобы не дублировать существующее задание Sites. prices.yml уже содержит расписание, но без vars.SITE_URL и secrets.PRICE_JOB_TOKEN работать не будет.
7. Проверить публичный каталог, сохранение и загрузку сборок, запрет неавторизованного обновления цен, реальное изменение checkedAt и отчёт обновления. Только после этого считать перенос завершённым.

## Проверка импорта

В GitHub загружены 188 файлов исходного архива. При импорте выполнены поиск файлов секретов и проверка типичных ключей. Полная сборка и внешняя публикация на момент импорта не подтверждены.
