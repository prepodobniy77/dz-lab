# Автоматическое обновление цен DZ LAB

## Исполнители

- Cloudflare Worker `dz-lab`: **06:00 и 18:00 МСК** (`0 3,15 * * *` UTC).
- GitHub Actions: резерв в 06:20 и 18:20 МСК. Пропускает успешный цикл текущего 12-часового окна либо успех менее шести часов назад. Есть ручной `workflow_dispatch`.
- GitHub Actions импортирует DNS в 06:40 и 18:40 МСК (`40 3,15 * * *` UTC), только если задан адрес фида.
- Связанное облачное задание Sites выключено.

[Настройка Cloudflare, D1 и секретов](EXTERNAL-HOSTING.md).

## Порции, источники и публикация

Каждая порция вызывается защищённым `POST /api/prices/sweep` и возвращает `{done,cursor,processed,report}`. Cron обращается к своему HTTPS-адресу с `PRICE_JOB_TOKEN`. Порции работают в отдельных вызовах Worker, а D1 хранит курсор и трёхминутную аренду, чтобы исполнители не обрабатывали одну порцию параллельно. Курсор обхода записывается по завершении порции. При прерывании порция повторяется с сохранённой позиции. Резервный workflow ждёт освобождения активной аренды и может обработать до 600 порций в пределах 32 минут. Внешний Worker обрабатывает карточки по одной за вызов, чтобы укладываться в лимит CPU. Для длинного цикла GitHub Actions продолжает с курсора Cloudflare. После полного цикла действует защитный интервал 660 минут.

Без дополнительных ключей основной обход проверяет XCOM. Сначала читается `robots.txt`, учитываются запрещённые адреса и паузы. При ограничении доступа запросы останавливаются. До публикации XCOM нужен охват не менее 80% известных предложений. Совпадение товара проверяется по артикулу или подтверждённой ссылке. Скачок цены более 50% уходит на проверку. Непроверенные позиции сохраняют прежние цену и дату.

По желанию можно подключить Delect и ИИ-поиск. Лимит поиска — до 50 товаров на цикл и суммарно 50 в сутки UTC (`AI_MAX_PRODUCTS_PER_DAY`), включая неудачные попытки. Второй запуск не удваивает платный лимит. Перенос старых наблюдений не делает цены свежими. Delect публикуется независимо от XCOM, с собственной проверкой охвата и общей арендой записи.

## Свежесть и мониторинг

[Исследование источников и требуемые доступы](PRICE-SOURCES.md). Контракт адаптера — `lib/providers/types.ts`. Предложения сохраняют тип источника, дату выгрузки, регион и валюту.

- До 12 ч: «Актуально», до 36 ч: «Проверено вчера», до 72 ч: «Могла устареть». Старше 72 ч не участвует в лучшей цене. Без свежих предложений — «Нет данных».
- `PRICE_XCOM_INTERVAL_HOURS`, `PRICE_DNS_INTERVAL_HOURS`, `PRICE_DELECT_INTERVAL_HOURS`: по умолчанию 12. Для DNS/Delect диапазон 1–12, для снимков 1–168. Это ограничение частоты запросов, а не отдельный планировщик. Для более частых обновлений понадобятся дополнительные окна исполнения; защитный интервал основного обхода — 660 минут.
- `GET /api/prices/sources`: расписание, источник, самая старая цена и последняя успешная публикация по магазинам. Один новый товар не обнуляет возраст остальных.
- `/admin/prices`: защищённая панель владельца. Ключ вводится в поле пароля, передаётся в заголовке и не сохраняется в браузерное хранилище. У подключённого источника без свежих наблюдений более 26 ч — красное предупреждение.
- Если URL DNS хранится только в GitHub, выставь в Worker `DNS_FEED_ENABLED=1` для мониторинга. Без него неподключённый DNS не порождает ложных уведомлений.
- Необязательные `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID`: cron проверяет просрочку и отправляет сообщение не чаще раза в сутки на источник. Реальная доставка требует проверки; тесты используют подставной транспорт. При полной остановке cron внутренний монитор также не запускается.
- XCOM/Delect: скачок более 50% подтверждается двумя последовательными наблюдениями с разницей до 2%. Повтор той же даты не подтверждает скачок. Ожидание ограничено семью днями; прежняя цена сохраняет свою дату.

## Как проверить публикацию

Сначала сохрани исходный каталог. Затем запусти резервный workflow вручную или дождись окна Cloudflare Cron. При ручной проверке после недавнего успеха workflow пропустит обход.

```sh
curl -fsS https://dz-lab.dimkaaistov.workers.dev/api/catalog -o .sites-runtime/catalog-before.json
gh workflow run prices.yml --repo prepodobniy77/dz-lab --ref main
gh run list --repo prepodobniy77/dz-lab --workflow prices.yml --limit 3
```

После завершения сохрани новый каталог и запроси публичный статус.

```sh
curl -fsS https://dz-lab.dimkaaistov.workers.dev/api/catalog -o .sites-runtime/catalog-after.json
curl -fsS https://dz-lab.dimkaaistov.workers.dev/api/prices/sweep
```

В публичном статусе сверяй `lastSuccessfulAt` и `lastSuccessfulUpdated`. Для истории открой защищённый `GET /api/prices/status` с `Authorization: Bearer <PRICE_JOB_TOKEN>` или запроси D1 через Wrangler.

```sh
pnpm exec wrangler d1 execute dz-lab-db --remote --config wrangler.jsonc --command "
SELECT checked_at, json_extract(error,'$.trigger') AS trigger,
       json_extract(error,'$.status') AS status,
       COALESCE(json_extract(error,'$.updatedOffers'), json_extract(error,'$.updated')) AS updated
FROM source_health WHERE store LIKE 'PRICE_SWEEP_RUN:%'
ORDER BY checked_at DESC LIMIT 5;"
```

Завершённый цикл с опубликованными ценами даёт новую запись в истории и более свежие `checkedAt` у тех же предложений в `/api/catalog`. История показывает источник запуска `cron` или `github`. Для подтверждения именно Cloudflare Cron нужен цикл с `trigger=cron`. При ошибке сохраняются безопасная причина и запись в истории, а предыдущий успех остаётся видимым. Свежие даты появляются только у опубликованных проверенных цен.

## Как подключить фид DNS

Нужна разрешённая для DZ LAB выгрузка обычных розничных цен и наличия по Москве в рублях. На 7 ноября 2026 года `robots.txt` DNS для общего агента разрешал обычные пути каталога и параметр `?page=`, ограничивал произвольные параметры, поиск и служебные пути. Прямой GET московского каталога процессоров вернул HTTP 401. Автообновление принимает только предоставленный фид. [robots.txt DNS](https://www.dns-shop.ru/robots.txt) · [Правила пользования сайтом DNS](https://www.dns-shop.ru/rules/site-usage/)

1. Примени миграции `pnpm exec wrangler d1 migrations apply dz-lab-db --remote --config wrangler.jsonc` перед деплоем Worker. Сборка Cloudflare выполняет `pnpm run build` с `WORKERS_CI=1` и готовит статические файлы внешнего Worker без доступа к D1 или секретам. Миграции — отдельный шаг.
2. В GitHub Actions Variables добавь `SITE_URL=https://dz-lab.dimkaaistov.workers.dev` и `DNS_FEED_URL`. Если URL содержит подпись или секретный параметр, сохрани его в Secret `DNS_FEED_URL`. Для Bearer-авторизации поставщика задай Secret `DNS_FEED_TOKEN`. `PRICE_JOB_TOKEN` должен совпадать в секретах GitHub и Worker.
3. Используй конечный HTTPS URL. CLI скачивает не более 10 МиБ за 60 секунд и отправляет токен только на origin настроенного фида. Переходы на другой origin блокируются. Если `DNS_FEED_URL` пуст, расписание пропускает загрузку.
4. Для первого реального прогона запусти workflow «Импорт прайса DNS» на `main`. Сверь `updated` в `GET /api/prices/import` и `checkedAt` изменившихся предложений в `/api/catalog`. Защищённый `GET /api/prices/import?details=1` показывает журнал последних импортов, курсор, охват, конфликты, причину отклонения и `rowsWritten`. В публичном ответе доступны только магазин, время завершения, статус и число обновлённых позиций. Магазин появляется в статусе при наличии подтверждённых цен.

### Формат, свежесть и ручная загрузка

Фид должен быть в UTF-8. Поддерживаются YML (`<yml_catalog date="…">` и `<shop><offers><offer>`), XML (`<offers date="…"><offer>`) и CSV с запятой или точкой с запятой. Столбцы CSV — `mpn,sku,url,price,availability,date,currency`. В YML артикул производителя берётся из `vendorCode`. Цена должна быть числом больше нуля, валюта — RUB. Для наличия подходят `true`, `false`, `in-stock`, `out-of-stock` и `unknown`.

Дата берётся из содержимого. Для HTTP-источника без даты CLI проверяет `Last-Modified`. Если нет обоих, плановый запуск завершается ошибкой. Время без часового пояса считается московским. Максимальный возраст — 36 часов. Чтобы изменить его, задай одинаковый `FEED_MAX_AGE_HOURS` в GitHub Variables и переменных Worker. Более старая выгрузка отклоняется со статусом `stale`.

Для ручного запуска задай `SITE_URL` и `PRICE_JOB_TOKEN` в защищённом окружении. Если в локальном файле нет даты, передай фактическую дату формирования через `--date` или `X-Feed-Date` для HTTP.

```sh
node scripts/import-feed.mts ./dns-moscow.xml
node scripts/import-feed.mts ./dns-moscow.csv --date=2026-11-07T18:00:00+03:00
```

Файл можно отправить целиком как тело `POST /api/prices/import` с `Content-Type: application/xml` или `text/csv` и `Authorization: Bearer …`. Магазин по умолчанию DNS. Для другого поддерживаемого магазина передай `X-Feed-Store` или `--store`. Для больших файлов используй CLI: он отправляет по 100 строк и продолжает прерванную загрузку с сохранённой порции, если повторно запустить его с тем же файлом и параметрами.

### Правила публикации

- Для известного магазина нужен охват 80% каталога по уникальным совпадениям MPN, SKU или URL с валидной ценой. Если известно меньше 100 позиций, владелец явно подтверждает первый импорт флагом `--bootstrap` или `bootstrap=1`. Тогда порог считается от уникальных распознанных позиций фида, включая позиции с невалидной ценой. Для новой карточки нужны однозначный MPN и URL магазина. Конфликтующие строки исключаются из числителя.
- При подтверждённом сужении ассортимента владелец может использовать `--force` или `force=1`. Решение сохраняется в защищённом журнале. Для публикации всё равно нужна хотя бы одна валидная строка. Флаг не отменяет правила даты, идентификации, bootstrap и проверки скачков.
- Скачок более 50% остаётся на проверке. Он подтверждается, если в следующей принятой выгрузке с более поздней датой цена отличается от ожидающей не более чем на 2%. Повторная отправка той же даты не считается второй выгрузкой. Через семь дней неподтверждённая запись удаляется, сохраняя предыдущую цену с её датой.
- Для ручной проверки используй защищённый `GET /api/prices/import/reviews`. Следующую страницу можно запросить через `?after=<nextCursor>`. В `POST /api/prices/import/reviews` передай JSON с `store`, `productId`, `checkedAt` из ответа и `action: "accept"` или `"reject"`. Если предложение уже изменилось или истекло, сервер вернёт 409.
- На магазин разрешён один незавершённый импорт. Повторный старт возвращает 409. Если в момент запроса аренду удерживает другой вызов, сервер возвращает 429 с `Retry-After`. Публикация и порции XCOM используют общую трёхминутную аренду D1. GitHub workflows также запускаются последовательно.
- Публикация сохраняет статус `publishing`, а цены, историю и итог фиксирует одной транзакцией D1. При сбое отправь тот же файл повторно. Незавершённые импорты старше двух часов помечаются брошенными, их строки удаляются. После публикации или отклонения временные строки удаляются сразу, записи журнала хранятся семь дней. У пропущенных позиций и при повторе той же выгрузки даты сохраняются. Новая подтверждённая выгрузка обновляет дату даже при прежней цене. История создаётся только при изменении цены.

### Лимит D1

D1 Free даёт 100 000 записанных строк в сутки на аккаунт, включая изменения индексов. `rowsWritten` складывает метрики подтверждённых операций импорта; аренда, запись счётчика и внешняя уборка учитываются отдельно. Локальный замер на искусственных 8 144 позициях: перенос снимка с новой датой без изменения цен — 48 959 строк; следующие импорты с изменением всех цен — по 40 813. Это тестовые данные, не цены DNS. На служебные записи добавь около 250 строк на импорт.

Два массовых изменения DNS дают около 82 126 записей в сутки. При прежней ориентировочной оценке XCOM 6–10 тыс. за цикл получается **94–102 тыс. записей в сутки**, без других баз и Delect. Есть риск превышения Free; день переноса исходного снимка может стоить дороже. Измерение Miniflare не заменяет метрики Cloudflare. Перед подключением полного фида нужно измерить реальный расход и согласовать объём либо другой способ хранения. Платный план не подключался. [Лимиты D1](https://developers.cloudflare.com/d1/platform/pricing/)

Можно ли получить разрешённый фид розничных цен и наличия DNS для Москвы с правом показывать цены и ссылки на карточки в DZ LAB? Нас интересуют процессоры, материнские платы, видеокарты, настольная оперативная память, SSD, HDD, блоки питания, корпуса и охлаждение.

Пришлите, пожалуйста, пример файла, условия использования и допустимую частоту запросов. Планируем запрашивать фид два раза в сутки, около 06:40 и 18:40 МСК.

## Архив импортов

### Каталоги Регарда и Ситилинка

Публичный снимок для Москвы, в рублях. Импорт охватывает те же 10 категорий
конфигуратора. SO-DIMM не импортируется ни из одного магазина. Не используйте
зачёркнутую цену, кредитный платёж, цену другого продавца или карточки без цены.

- Регард: `node scripts/collect-regard.mts` читает открытые страницы с учётом
  robots.txt, с паузами между запросами. При HTTP 429 сбор останавливается;
  уже сохранённые страницы остаются в `.sites-runtime/store-snapshots/`.
- Ситилинк: просмотрите открытые разделы в браузере с выбранной Москвой.
  `node scripts/receive-citilink-snapshots.mts` принимает снимки через
  локальную форму на `http://127.0.0.1:5195/`. Сохраняйте все карточки страниц,
  включая позиции без цены, для проверки покрытия. На странице охлаждения
  собраны и кулеры, и СЖО.
- `node scripts/import-store-catalogs.mts` показывает покрытие и пропуски.
  Запустите с `--apply`, чтобы записать каталог и `data/store-coverage.json`.
  Сохраняются URL и время каждого наблюдения; разные артикулы и уценка не
  объединяются по похожему названию. Каталог меняется после публикации сборки.

### Адаптированные конфигурации DZ LAB

Вместо четырёх магазинных ПК в галерее размещены редактируемые DZ LAB Start,
Balance, Pro и Ultra. За основу взяты публичные конфигурации PCS, «Точки ПК»,
DigitalRazor и BIT COMP. Названия, описания и конкретный выбор деталей — наши.
Ссылки, дата исследования, базовое сочетание CPU/GPU и перечень изменений
хранятся в `data/ready-build-adaptations.json` и доступны в составе сборки.
Изображение показывает реальный корпус из каталога, а не чужой готовый ПК.

`node scripts/adapt-ready-builds.mts` применяет только четыре проверенные
замены, сохраняя остальные 16 основ. Перед записью проверяются ID/категории
компонентов, наличие цены и выявляемые конфликты совместимости. Повторный
запуск не создаёт дубликаты. Общий генератор `scripts/create-ready-builds.mts`
тоже сохраняет эти адаптации по `adaptation.replaces`.

Цена каждой сборки рассчитывается в `lib/ready-builds.ts` по доступным ценам
конкретных деталей. Цена компьютера из исходного магазина не переносится.
Сборка, доставка, Windows и фирменная гарантия магазина не включены. Карточки
источников не означают партнёрство или точное воспроизведение их комплектации.
Параметры, которых нет в каталоге, остаются предупреждениями совместимости.

### Подбор материнских плат

Для каждой из 20 конфигураций задана проверенная модель в
`data/ready-board-plan.json`: ID платы, назначение, обоснование и источники.
Генератор больше не выбирает минимальную цену по сокету/чипсету. Если модель
исчезнет из каталога или у неё пропадёт цена, генерация останавливается и
требует пересмотра; молчаливой замены на дешёвую плату нет.

`node scripts/update-ready-motherboards.mts` применяет план только к платам,
сохраняя остальной состав. `create-ready-builds.mts` и `adapt-ready-builds.mts`
используют тот же план; адаптации должны явно отражать замену платы.

B650M-R сохранена в одной начальной AM5-конфигурации. Для Ryzen 5/7 использованы
Pro RS, MORTAR и GAMING PLUS, для X3D — TOMAHAWK MAX, для Ryzen 9 — TUF X870 и
AORUS X870E. Для i5-14600KF выбрана B760M-A WIFI DDR4. Основание — оснащение и
питание конкретной модели, а не обещание прироста FPS от более дорогого чипсета.
Поддержку конкретного CPU/BIOS, QVL памяти и разделение линий M.2/PCIe следует
проверять по документации. Проверка сокета не является тестом VRM под нагрузкой.
